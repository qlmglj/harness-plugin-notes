# 插件安装与配置清单

按顺序执行，每步都有"怎么判断成功"。

## 1. 安装

```bash
dsh plugin --profile desktop add <包名>
```

判断成功：命令输出里出现包名与版本号，且 `package.json` 的 `dependencies` 多了这一项。
若界面没出现新面板，先刷新页面（Ctrl+R）再判断——宿主进程热挂载与前端 UI 加载是两件事。

## 2. 配置凭证

优先级从高到低：

1. 界面「设置 → 凭据」里新建，**键名只能用字母、数字、下划线**（`AGNES_API_KEY` 这类 POSIX 标识符）。带 `-` 的名字会让整份凭据文件解析失败，表现为"填了没反应"。
2. 环境变量 `AGNES_API_KEY`（重启应用后生效）。
3. 应用目录下的 `.env` 文件（启动时加载）。

判断成功：插件状态接口返回 `configured: true`。

## 3. 验证

```powershell
./scripts/health_check.ps1
```

预期输出：HTTP 200 与可用模型数量。返回 401 说明 Key 无效，403 说明 Key 档位不含该模型。

## 4. 常见误判

| 现象 | 真实原因 |
| :-- | :-- |
| 面板不出现 | 只重启了窗口，没重启进程（环境变量在启动时读取） |
| 配了 Key 仍显示未配置 | 凭据键名不合法，整份文件解析失败 |
| 换模型报 403 | Key 档位不含该模型，不是代码问题 |
| 状态接口 503 | 上游服务不可用，与本地配置无关 |
