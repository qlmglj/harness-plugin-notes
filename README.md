# DeepSeek Harness 插件踩坑复盘


> **对应简历**「DeepSeek Harness 插件部署与故障排查」：400 / 403 / 503 三类接口故障的完整定位过程与可复用排查顺序。

给 AI 桌面端（DeepSeek Harness）装第三方插件时，真实遇到的三类接口错误：**400 / 403 / 503**。
每一类都记下：现象 → 排查路径 → 根因 → 修复 → 如何避免。

这不是"教程"，是一次**接口调试的完整推理记录**。排查顺序可以复用到任何 HTTP 接口对接。

## 三类故障对照

| 故障 | 表面现象 | 根因 | 定位手段 |
| :-- | :-- | :-- | :-- |
| 400 Bad Request | 请求发出即失败，报"请求体校验不通过" | 请求体结构与接口约定不符（字段名/枚举取值错误） | 读插件源码里的请求构造，与文档字段逐一比对 |
| 403 Forbidden | 换个模型就失败，提示权限不足 | 当前 API Key 的档位不含该模型 | 用 `/v1/models` 列出该 Key 真实可用的模型清单 |
| 503 Unavailable | 状态接口显示"未配置"，但 Key 填了 | 上游模型服务暂时不可用 / 该模型当日额度耗尽 | 区分"凭证问题"与"上游问题"：先查状态接口再查模型清单 |

## 排查方法论

1. **先分清"谁的错误"**：客户端构造（400）、鉴权档位（403）、上游服务（503）——三类对应三种修法，混着猜最耗时。
2. **用最小请求复现**：`curl` 直接打接口，绕开插件，确认是插件问题还是服务端问题。
3. **以服务端返回为准**：状态接口里 `configured: false` 有两种可能（没 Key / Key 无效），必须再打一次 `/v1/models` 才能区分。
4. **修复后回归**：同一请求重放，记录状态码从 X → 200 的变化，而不是"看起来好了"。

```powershell
$env:AGNES_API_KEY = "sk-..."          # 只在当前终端生效，不落盘
powershell -ExecutionPolicy Bypass -File ./scripts/health_check.ps1
```

> Windows 默认禁止运行 .ps1 脚本，报"禁止运行脚本"时用 `-ExecutionPolicy Bypass`（只对本次执行生效，不改系统设置）。
